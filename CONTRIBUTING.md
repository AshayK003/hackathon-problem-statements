# Contributing

We welcome contributions that make this the best repository of real-world hackathon problem statements.

## Ways to Contribute

1. **New problem statement** — Use `_PROBLEM_TEMPLATE.md`. Place it in the appropriate track directory.
2. **Improve existing** — Update datasets, fix inaccuracies, add references, refine scope.
3. **Implementation notes** — If you built a solution to one of these problems at a hackathon, add a `_implementations/` folder with your notes, architecture, and lessons learned.
4. **New track** — Propose a new category (e.g., "Climate Tech", "Healthcare", "Fintech for Good").

## Guidelines

- **Real problems only** — Every statement must be grounded in actual data, users, or research.
- **No chatbot wrappers** — No "AI that does X as a chatbot" unless there's a genuinely novel angle.
- **Be specific** — Link datasets, APIs, papers, and existing OSS. Scope the MVP.
- **One file per problem** — Place it under the right track directory.
- **Follow the template** — Use `_PROBLEM_TEMPLATE.md` for new submissions.

## Contributors

We appreciate every contribution to this repository.

Once your pull request has been merged, you're welcome to add yourself to the `CONTRIBUTORS.md` file.

Please include:

- Your name
- GitHub username
- Your role
- Contribution type(s) using the emoji legend

Example:

| Name | GitHub | Role | Contributions |
|------|--------|------|---------------|
| Jane Doe | @janedoe | Contributor | 💻 Code, 🐛 Bug Reports |

This project follows the [Contributor Covenant](CODE_OF_CONDUCT.md). Be respectful, constructive, and inclusive.
